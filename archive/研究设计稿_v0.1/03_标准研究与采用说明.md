# 教学数据与课件交换标准研究及采用说明

研究日期：2026-10-23｜与架构及规范草案 v0.1 配套

## 一、研究方法与结论边界

本次以 IEEE、ISO、1EdTech、W3C、ADL/AICC 官方规范仓库、教育部和标准项目官方网站为主要来源，检查标准名称、适用对象、版本及可访问页面标明的发布状态。对国内五份相关标准下载了教育部正式 PDF 并核查封面和相关章节。未将商业介绍、产品宣传或搜索结果中的转载日期当作标准发布日期。

“研究采用”指选择适合本校场景的对象、语义和协议组合；不表示当前应用已经实现，不表示逐条通过全部标准的一致性验证。国际标准中的候选规范、付费全文及此次无法取得的运行时细节，分别记录边界。

## 二、先统一几个名称

**xAPI 与 Tin Can API 是同一条技术路线。** ADL 的术语说明将 Tin Can API 解释为 xAPI 的旧称；无需把二者作为两个独立标准建设。[ADL xAPI 术语说明，R03](https://github.com/adlnet/xAPI-Spec/blob/master/xAPI-About.md)

**此处课件标准的规范写法是 SCORM。** SCROM 通常属于字母顺序误写；Scrum 是团队开发与管理框架，与课件交换属于不同问题。本体系将 SCORM 纳入兼容研究，将 Scrum 排除在教学数据交换规范之外。[Scrum Guide，R25](https://scrumguides.org/scrum-guide.html)

**xAPI、cmi5、SCORM、LTI 不能互相替代。** xAPI 记录和交换学习经历；cmi5 为基于 xAPI 的可运行学习单元规定启动和运行约束；SCORM 面向既有 LMS 课件运行生态；LTI 连接远程教学工具。课程资料打包、题目交换、目标框架、认知状态仍需各自模型。

## 四、为什么不能只选一个标准

### 4.1 课程包与课件交换

建议建立四级交换视图：文件表示形式、单个可运行资源、课程组织包、校内完整教学资产包。PPTX/PDF/HTML/EPUB 等表达内容；H5P、SCORM 或 cmi5 表达特定运行资源；Common Cartridge 组织跨系统课程资源；校内资产包连接原始来源、过程证据、认知状态及权限。

Common Cartridge 1.3 可作为成熟兼容入口，但不应假定它原生完整表达 QTI 3、所有新式 LTI 服务或本校认知模型。官方说明中的 CC 1.4 增加了 QTI 3 包、较新 LTI 及相关元数据支持，当前仍以候选状态对待。新旧版本之间需要明确映射及有损部分。[Common Cartridge 官方说明，R07、R08](https://www.1edtech.org/standards/cc)

Thin Common Cartridge 和 LTI 链接只保证在相应环境下连接内容的机制，不能据此承诺完整字节、可编辑源或脱离远程服务后的运行。校内包因此要独立登记访问依赖及可恢复程度。

### 4.2 学习事件

xAPI 为事件传输和记录提供共同结构，但“发生了什么”的教学含义仍依赖约定。学校必须明确同一个 verb IRI 的含义、事件触发时机、对象粒度、关联课程和帮助条件。支持 xAPI 的系统若词表不同，仍可能无法进行一致的学习分析。[IEEE xAPI 条目，R01](https://standards.ieee.org/ieee/9274.1.1/7321/)

选择 xAPI 作为主路线的设计理由，是本项目需要覆盖课堂、在线任务、实训和 AI 帮助等多场景记录，同时希望形成学校自有 Profile。这是架构选择，不是声称 xAPI 在所有场景都优于 Caliper。已产生 Caliper 的系统可经受控映射接入，避免重复建设两套相互矛盾的事实库。

cmi5 Quartz 明确引用 1.0.3。建立新 xAPI 2.0 接入时，必须把 cmi5 的兼容运行约束纳入适配设计，并测试启动会话和完成/通过状态，不能仅替换请求头或版本字符串。[cmi5 References 与 Scope，R05](https://github.com/AICC/CMI-5_Spec_Current/blob/quartz/cmi5_spec.md)

### 4.3 学生认知状态

本次核到的标准分别覆盖经历、测评、能力框架和成果记录，没有一项能单独完整承载本项目要求的“具体目标下的认知状态＋证据＋帮助条件＋不确定性＋方法版本＋更新规则”。因此 S5 是本校需要明确制定的应用规范；它建立在现有标准可提供的对象和证据之上，不把本次检索范围扩大为“国际上不存在任何相关标准”的结论。

建议组合：以 CASE 标识目标和能力，以 QTI 表示测评内容，以 xAPI/Caliper 接收过程证据，以学校 CognitiveState 表达判断，以学校 LearningRecommendation 表达行动；经认可的成果以后再按 CLR/Open Badges 输出。交换标准不负责保证模型判断准确，必须另做学科测量和教学效果验证。

### 4.4 最新版本要看子规范

QTI 3 的题目和测验规范为 Final，但同一官方目录仍将 Results Reporting and Usage Data 标为 Public Candidate Final。本稿因此采用 QTI 3 的内容交换，成绩和过程结果使用校内规范及明确的服务映射，不把整个 QTI 3 家族的所有部分一并称为正式版。[QTI 规范目录，R09](https://www.1edtech.org/standards/qti/index)

CASE 1.1 当前页面头部标注 2025-01-24，修订历史又列出 2024-02-28。采用时记录精确 URL、获取日期和文本摘要/hash，避免仅凭一个年份识别规范快照。[CASE 1.1，R10](https://www.imsglobal.org/spec/case/v1p1)

## 六、首版采用组合

| 工作内容 | 首选组合 | 首版应补充的学校规则 |
|---|---|---|
| 课程与课件 | 学校完整资产包＋CC 1.3 兼容；EPUB/H5P 按需 | 源文件、版本、视频定位、权利、可恢复程度 |
| 题目与活动 | QTI 3；既有 QTI 2.x 按需适配 | 目标关系、AI 帮助、评分确认、损失报告 |
| 学习过程 | xAPI 2.0 方向＋1.0.3 兼容＋学校 Profile | 词表、事件触发、作品引用、对账、更正 |
| 可运行学习单元 | cmi5 Quartz 或既有 SCORM 兼容 | 运行依赖、启动、会话、完成/通过及退出 |
| 知识和能力 | CASE 1.1 | 学科扩展、跨课程映射审核及目标版本 |
| 认知与学习建议 | 学校 S5，对齐目标与证据标准 | 量尺、方法、证据、不确定性、有效期和复核 |
| 应用接入 | LTI 1.3＋需要的 Advantage 服务；后台服务按校内 API | 对象范围、用途、写入权限及退出 |
| 主数据 | 学校权威标识＋OneRoster 适配；跟踪 Edu-API | 人员/课程/开课/修读分离及撤权联动 |
| 保护与质量 | JY/T 0643、0661、0650；WCAG 2.2 | 分类映射、留存、可解释界面及互操作测试 |

CC 1.4、Edu-API 候选版以及 QTI 结果报告候选子规范属于跟踪项。SCORM 是存量兼容项。CLR/Open Badges 是后续成果输出扩展。学校认知规范是本项目的新增语义设计，不能被写成已经获得外部标准组织认可。
