# WP5 AI 评分提议接入样例

面向《智慧教学-数据模型标准》的第三方厂商。样例声明 **P-COM + P-AI + P-GRD（仅提议）**，按 9.5.1 a) 仅提交待人工确认的评分提议。它不承担确认、归档、更正、发布、导出、发放授权或学习者形成性反馈，不使用真实大模型或外发数据。

**证据范围：合成样例通过（4.4.5.2）**。这不是认证，也不是完整 Profile、D2 冻结、真实平台数据、教学效果或真实试点的证据。

## 运行与验收

Python 3.11+。从仓库根安装 WP1 锁定依赖：`python3 -m pip install -r 验证/契约/requirements.txt`。需要 WP2 参考服务（PR #52）。一条命令运行：

```sh
python3 -m pytest 验证/AI接入样例 -v
```

测试自动启动隔离的回环 WP2 进程及临时 SQLite 审计文件；无须预启服务、配置外部凭证或修改夹具。样例只通过 [WP2 OpenAPI](../参考公共服务/openapi.yaml) 的 HTTP JSON 接口连接服务，不导入其 Python 实现或读取其数据库。使用 [WP1](../契约/README.md) 本地候选 Schema/词表及校验器。

| 验收 | 合成可观察结果 |
|---|---|
| T08-P | 受权读取作品与量规；保留作品/制品、量规、方案、方法版本与来源。保存的 `GradeDecision` 为 `proposed`，`grade.proposed` 有业务回执，正式视图为空；小组成员分别提议、共享提交及成员快照。未承担 AGS。 |
| 越权确认与归档反例 | 测试驱动用服务身份尝试取得确认 scope、请求确认、冒充教务回执；WP2 拒绝并记录审计，提议和正式视图不变。样例正常流程没有这些操作。 |
| T11（选定） | 同课越权作品、跨开课、未授权量规版本、过期令牌和错误受众被拒；撤权前读取成功、撤权后旧凭证即使面对同一内容源也不能再读取作品或量规。应用记录受限读取，WP2 记录授权校验及撤权。 |
| T25 | 测试驱动提交伪造 `auth_context`，WP2 拒收并审计；已受理事件的接收端上下文能回溯到实际写入凭证的摘要与具体授权记录。 |

## 第三方厂商接入指南

1. **登记能力和责任。** 与学校确定 P-COM、P-AI、P-GRD 的适用版本、P-GRD 只承担 T08-P；依据 9.1、9.4 登记应用实例、任务与输出类别。评分提议不进入正式记录，只有授权人员能在另一责任主体的流程中复核和确认（7.5、9.2.4、9.5）。样例的 `PROFILES`、`P_GRD_STAGES` 是本应用的候选声明，不是 WP2 能力目录的批准。任务的开课、修读、学习者、有效提交、方案及量规版本来自可信的学校编排，不从自由文本或评分器输出推导。
2. **取得并绑定最小权限。** 按 8.6 取得任务级、短时、限受众的客户端凭证，学校登记用途、时限、开课及确切作品/量规引用。由可信的令牌提供方组装 `Credentials`，把 `grant_ref` 和相应令牌一起绑定到可信任务；不接受用户、作品或评分器提供这些值。样例只需读取所需权限、`grade.propose` 和 `events.write`；WP2 的合成写凭证每次写入使用不同令牌。用户委托确认另行办理，AI 凭证不应包含人工确认或其他高风险操作。
3. **在内容边界实时校验再读。** WP2 提供 `POST /grants/validate`，当前不交付作品内容或量规；本样例用 `SyntheticContent` 代替学校内容端。每次读先持读取凭证查询当前授权，再校验用途、开课及确切对象引用，成功才查合成夹具；不存在、越权、撤权或服务校验失败均不返回内容。生产上应由学校的内容服务/源应用对实际令牌及其绑定授权执行对象级鉴权，并实施撤权后的缓存、副本及在途任务处置（8.8、11 章）。不要以夹具接口或客户端自查代替生产端授权。
4. **隔离评分输入和写权限。** `ProposalApp.propose(task, credentials, request_text=...)` 仅把作品文本和量规数据交给 `Scorer.score`（无凭证、HTTP 客户端或工具）；自由文本不参与任务编排。默认 `FirstLineScorer` 按合成量规精确匹配第一行，产生固定分数，方法通过 `method_ref` 指定具体登记版本。替换点是 `Scorer`，不是 API 权限；任何工具请求均被拒。样例只验证受控桩行为，不把可执行 Python 插件视为经过隔离的不可信代码，也不提供模型网关或真实模型接线。
5. **提交候选对象和事件，查验业务回执。** `POST /grades/proposals` 保存经 WP1 校验的 `GradeDecision(decision_status=proposed)`，并按 WP2 候选参数传递 `learner_ref`、`submission`、`method_ref`、`source_refs`；`POST /events` 写入引用该决定的 `grade.proposed` input 事件。不要填写接收端的 `event_id`、`received_at`、`auth_context`。调用返回决定与回执，检查业务 `status`，而不是只看 HTTP 200；两次写入不是原子事务，事件失败时保留决定引用与回执进行对账，不盲目重跑评分。生产端应保留稳定源事件标识、请求与回执，落实 7.6、8.7、8.8 的幂等重放及对账要求。样例尚未实现持久化源端重试队列。
6. **保留受限读取和拒绝证据。** 样例用 `Audit` 写 SQLite，关联任务、授权、目标及结果，不记凭证、作品内容或提示原文。WP2 拒绝、事件认证上下文与回执由公共服务留证。正式接入还须使用学校要求的受控访问、审计外送及防篡改存储（11.10），并执行相应 T 用例。
