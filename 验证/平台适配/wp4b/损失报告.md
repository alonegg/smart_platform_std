# WP4b 数据损失与验收

## 量化口径（4.4.5.2、8.2.5、12.3）

[逐要素 CSV](loss.csv) 包含矩阵 166 个要素 × 两平台，其中 WP1 首批 148 个要素均覆盖。每行列条款、观察数、转换数、证据等级、静态判定与差异、理由、来源和产出文件。补齐方指**这一路径的首要缺口**，不是唯一工作方，也不评价平台整体能力。

| 判定 | 含义 |
| --- | --- |
| 已转换 | 对象/事件须整体通过候选校验；字段可单独转换，即使父记录被阻断。 |
| 需公共服务补齐 | 需要学校身份、权利、授权、存储、教务、接收服务或权威登记。 |
| 需平台扩展 | 源端须补采集、可核验版本/状态或时点快照；不能靠字段转换猜测。 |
| 无法取得 | 本批没有可复核的事实或未执行相应场景；不表示平台永远不支持。 |

观察数是关联到该要素的候选行或旁证行数。同一个事实的 tracking、xAPI、Caliper 可能各有旁证，**不相加为事件数**。转换数不是源端完整率。无动态证据的行标为静态推断／未执行，不计为差异；清单另附确实运行的离线写读检查。WP1 允许跳过的引用解析、受理权限与业务先决条件均未通过本试验证明。

## 与静态矩阵的差异

全部差异逐平台逐要素见 [differences.csv](differences.csv)。分值 2/3 指静态可适配/原生潜力，不意味着 WP4a 含所有取值；分值 0/1 上观察到转换也只证明本批场景。Open edX 部署版本与静态快照不完全相同，见 [WP4a 版本表](../README.md#两平台部署版本与源码快照)。

| 方向 | 平台与要素 | 动态结果 |
| --- | --- | --- |
| 实测范围高于弱对应 | Moodle：OBJ-029、EVT-011、FLD-EVT-015/016/020 | 三条持久化答题步骤可接上 quiz attempt 和答题数据，生成通过 WP1 的 input；无接收证据。 |
| 实测范围高于弱对应 | Open edX：FLD-EVT-015/016/020 | 六条 tracking 有短答案，五条能同秒对账到原生历史尝试及作品；另一条跨秒，未强接。没有 tracking 源事件键，整条不通过。 |
| 实测低于可适配潜力 | 两平台 OBJ-001/013；Open edX OBJ-004/014 | 有身份键和结构快照；无权威身份/权利，或未证明归属的具体课程版本。LearningUnit（OBJ-013）是 WP1 首批外依赖，候选包也没有该 Schema。 |
| 实测低于可适配潜力 | Open edX EVT-002 | 历史确认本地状态变化，ERB 有对应动词；未证明校级修读语义及采集实例，未发出候选事件。 |
| 实测低于完整契约交付 | 两平台 FLD-MAN-005/009；Moodle FLD-MAN-003 | Moodle 有原生备份任务号，但不能充当转换后诊断包的权威导出任务。两平台可列实际文件和 SHA-256、写候选 Schema 版本，未组成通过校验的交换清单。 |

据此细化**适用边界**，不声称推翻源码中存在的能力；例如 WP4a 无受控存储部署，不应据此降低平台的文件定位能力。相同字段的低/高分不是同一条端到端符合性结论。
