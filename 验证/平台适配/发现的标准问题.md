# WP4a：两平台可能标准问题与适配风险汇总

本文件服务于“智慧教学-数据模型标准”评议，按[评议意见模板](../../.github/ISSUE_TEMPLATE/review-comment.yml)字段汇总，不创建Issue、不修改标准、不实施WP4b转换。证据范围按4.4.5标注：原生平台合成数据不是认证、真实教学有效性或符合性声明。以下是适配风险/样例建议，不是已确认标准缺陷；未实测的链路不得推定已存在或不可实现。

## 1. 原生选课变更通知与完整状态变化事实的边界

- **条款位置（clause）**：5.2.8、7.3.1表7-2；矩阵OBJ-007、EVT-002。
- **评议类别（category）**：互操作。
- **参与身份（role）**：其他参与者。
- **应用类型与能力 Profile，或专业方向（profile）**：选课数据治理、平台适配；不声明已实现Profile。
- **具体问题与场景（problem）**：Moodle暂停/恢复调用产生日志，但other没有旧/新status，当前选课已恢复，不能仅凭两条更新日志恢复状态顺序。Open edX退选/重选另有原生history，需按history_date而非随机UUID主键排序。不能因另一平台有历史就补造Moodle历史。
- **建议条文或方案（proposal）**：适配指南区分通知、当前状态和历史事实；缺证时报告，不把日志条数当作完整状态链。后续研究实时同步留存前后状态，不直接修改正文要求。
- **技术或业务依据与影响范围（rationale）**：[Moodle详细记录第1项](moodle/发现的标准问题.md)及其日志/选课表；[Open edX样本与历史说明](openedx/README.md)。仅限本次原生插件/API路径，不推断额外插件或实时订阅能力。

## 2. 两平台改分历史均不自动等于正式更正决定链

- **条款位置（clause）**：7.3.1表7-2；矩阵EVT-020。
- **评议类别（category）**：技术语义。
- **参与身份（role）**：其他参与者。
- **应用类型与能力 Profile，或专业方向（profile）**：评分数据治理、授权及决定链。
- **具体问题与场景（problem）**：Moodle有60/70/85的grade history，Open edX有ORA评审和2→3.5/4覆盖历史；它们证明平台分数改变，未执行学校正式发布、授权审批、确认/归档及更正决定链。
- **建议条文或方案（proposal）**：补“原生历史存在但正式决定链缺失”的待补证/拒收样例；WP4b区分改分事实与正式grade.corrected，不补造授权、理由或决定编号。
- **技术或业务依据与影响范围（rationale）**：[Moodle第2项](moodle/发现的标准问题.md)、[Open edX第2项](openedx/发现的标准问题.md)。限默认模块本次调用，不判定学校流程/第三方审批插件不具备能力，不放宽正式更正条件。

## 3. ORA重置后的尝试计数重启与历史保全

- **条款位置（clause）**：5.1.8、5.2、7.5；矩阵OBJ-009、EVT-013。
- **评议类别（category）**：互操作。
- **参与身份（role）**：其他参与者。
- **应用类型与能力 Profile，或专业方向（profile）**：任务尝试身份与原始证据保全。
- **具体问题与场景（problem）**：Open edX员工重置后，两份不同UUID/文本的ORA提交共享student_item且attempt_number均为1，旧D行被默认manager隐藏；Moodle reopen则保留attemptnumber 0/1。不能把平台计数直接当成统一TaskAttempt身份，不能用默认manager的单行输出推断只有一次提交。
- **建议条文或方案（proposal）**：增加“重置后计数重启”和“软删除历史仍需保全”的适配样例；本次保留原生标识、状态、时间和取消事实，统一身份分配留WP4b。
- **技术或业务依据与影响范围（rationale）**：[Open edX第1项](openedx/发现的标准问题.md)、[Moodle场景及样本说明](moodle/README.md)。仅执行员工重置替代路径，未启用ORA自助重交，不能称平台没有重交功能。

## 4. 当前小组成员与形成时成员快照（变更场景未执行）

- **条款位置（clause）**：5.2.5、7.1.4 a)、7.2表7-1；矩阵OBJ-012、FLD-EVT-014。
- **评议类别（category）**：验证条件。
- **参与身份（role）**：其他参与者。
- **应用类型与能力 Profile，或专业方向（profile）**：小组学习证据的时点一致性。
- **具体问题与场景（problem）**：Moodle有group/grouping/组作业，Open edX有cohort及当前成员；两平台均未执行提交后退出/迁移，Open edX未创建teams/团队提交。因此不能用当前关系自动填历史member_refs，也不能断言历史必然不可恢复。
- **建议条文或方案（proposal）**：后续补成员加入/退出前后事件与快照校验，不改变标准已有时点要求；未完成前保留“未执行”标记。
- **技术或业务依据与影响范围（rationale）**：[Moodle第3项](moodle/发现的标准问题.md)、[Open edX第4项](openedx/发现的标准问题.md)。现有表只证明本次配置，时间恢复能力尚未验证。

## 5. 原生保存、ERB转换与标准事件符合是三个层次

- **条款位置（clause）**：7.1—7.3、表7-1；矩阵OBJ-029、FLD-EVT-004。
- **评议类别（category）**：验证条件。
- **参与身份（role）**：其他参与者。
- **应用类型与能力 Profile，或专业方向（profile）**：事件采集、外部协议与学校事件Profile。
- **具体问题与场景（problem）**：固定ERB对99条Open edX tracking投影输出76条xAPI及37个Caliper envelope；6条problem_check因原始referer为空而xAPI转换失败，ORA创建/评审等没有对应registry。外部协议版本不等于学校profile_id/profile_version，转换成功也不证明标准载荷完整。Moodle原生日志未在本次转换为标准事件。
- **建议条文或方案（proposal）**：验证记录分别列原生保存、转换完成和标准业务约束；保留输入、异常和不支持类型，不丢弃后宣称全覆盖，不补造缺失字段。
- **技术或业务依据与影响范围（rationale）**：[Open edX第3项](openedx/发现的标准问题.md)及[ERB实测报告](openedx/samples/erb-report.json)。原始六条referer也为空，已排除只是投影删除导致的解释；没有LRS传送或标准符合性执行证据。
