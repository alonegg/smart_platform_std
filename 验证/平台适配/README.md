# WP4a：真实平台取样总览

本包服务于“智慧教学-数据模型标准”的平台适配研究：在隔离的Moodle、Open edX中用合成课程、学员、教师和媒体运行场景，保留平台原生导出、来源、版本和证据边界，供后续适配与损失量化复核。

**不做标准契约转换、标准事件补造或损失量化；这些属于WP4b。** 原生课程ID、尝试计数、成绩历史、xAPI/Caliper字段不自动等于标准对象/事件。取样manifest只是文件来源/hash库存，不是标准交换manifest，也不是WP1候选契约的实例。

基于本包样本的候选转换、损失报告与测试入口见 [WP4b](wp4b/README.md)。

## 一条命令运行全部离线测试

在仓库根目录执行（Python 3.11+，仅标准库）：

```sh
python3 验证/平台适配/run_tests.py
```

入口依次运行总包校验、Moodle全部test_*.py、Open edX全部test_*.py，分别使用独立Python子进程，避免两平台同名test_samples/export模块相互污染。无需启动容器、安装Tutor或联网；检查已提交样本与脚本输入/输出保护，不重新部署、造数或取样。任一套件失败，整体返回非零；后续套件仍执行。详细测试名及各套件结果全部输出。

不要把无__init__.py的子目录交给一次递归discover后将“0 tests”当成功；上述入口显式发现两平台测试。总包测试额外校验两份追溯表的全部要素编号均存在于正式矩阵。

- [Moodle子目录](moodle/README.md)：42个样本/元数据文件，共270272字节；含用户及无用户MBZ、原生日志与表JSON。[追溯表](moodle/追溯表.csv)。
- [Open edX子目录](openedx/README.md)：39个文件，共258313字节；含两个OLX归档、表JSON、99条tracking投影、76条xAPI与37个Caliper envelope。[追溯表](openedx/追溯表.csv)。
- 两份追溯表共同构成本包追溯，不另建重复总表；编号源于[数据要素对照矩阵](../平台对标/数据要素对照矩阵.csv)。总入口及子目录测试检查编号存在、样本存在、各自声明场景无遗漏；不声称整个矩阵全覆盖。
- 原生表JSON只做明确的范围/安全投影；Open edX tracking删除敏感字段并JSON重编码，**不是逐字节原始日志副本**。xAPI/Caliper来自固定ERB，不是本标准转换产物。

按4.4.5.1—4.4.5.3区分以下证据范围，而不是把它们混成“平台通过认证”：

| 口径 | 本包含义 |
| --- | --- |
| 真实平台数据（合成课程/学员） | 由实际运行平台产生并留存的原生事实；仅支持总表声明场景，不证明真实教学或认知有效性 |

**没有本标准T用例的完整真实执行/符合性结论、国际认证或真实教学验证。** 部署曾遇到失败，但已恢复取得上述平台数据，没有继续用官方示例替代最终证据；历史故障见子目录README。

## 局限、保护与标准问题

1. 单实例、单次合成场景，非生产规模、安全审计或性能评估；没有真实个人数据。Moodle内建guest的root@localhost为默认本机值，其他导出邮箱为example.invalid。
2. 口令运行时生成且不入库外提交；不提交密码哈希/令牌/安全会话。详细白名单和字段投影见各自export_policy.json或export-policy.json及测试。原始运行日志/配置仅留忽略的.runtime。
3. seed重复执行拒绝既有场景；export默认写新临时目录，显式--update-samples也拒绝非空samples，复跑不改写已提交文件。离线总测试不自动部署/造数或更新样本。
4. ERB xAPI有6条problem_check因原始referer/context.referer为空而失败；Caliper本次无异常但有不支持事件类型，ORA创建/评审等未获对应转换输出。详见[erb-report.json](openedx/samples/erb-report.json)。未补造字段，不宣称全事件覆盖或外部协议认证。
5. 评分历史不等于正式更正决定，两个原生计数相同的ORA提交不能自动合并。风险汇总见[发现的标准问题.md](发现的标准问题.md)，它链接两平台详细条目并按评议模板记录；平台差异不是已确认的标准缺陷。

## WP1临时假设核对

**临时假设：无。** 已核对[WP1临时假设登记](../契约/临时假设.md)；本包没有引用其H-xx候选线格式、词表、阶段Schema或E12/E13等候选方案来构造标准数据，没有新增标准临时假设，也未修改WP1文件。

合成用户名、两个课程空间/run、原生重置流程和隐私投影是本次取样配置/平台事实，不是标准业务规则。文件SHA256只校验取样文件字节完整性，不是在选择标准事件摘要规范化方案；ERB的外部协议输出不等于采用WP1候选契约。WP4b若需使用候选约定，应另行引用/登记对应编号。
