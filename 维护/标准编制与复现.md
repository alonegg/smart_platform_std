# 标准编制与复现指引

本指引供标准维护机构使用，说明正文 12.6 的操作，不构成应用厂商必须复制的工具链。当前稿仍为征求意见稿；文稿生成和站点检查不代表正式受控包、两实现业务验证、学校审定或外部认证已经完成。

## 当前可执行流程

1. 在独立 Git worktree 修改当前评审稿 Markdown，以 Pandoc 同步生成同名 Word；需要版式检查时，使用独立 LibreOffice 用户配置转为 PDF，以 Poppler 提取文本及渲染检查。
2. 核对 Markdown 与 Word 全部编号段落及表格单元，执行条款引用、能力代码、外部登记、子用例和前置依赖检查。
3. 先提交候选文稿，再将站点 scripts/content.mjs 的 sourceCommit 指向该提交；构建器拒绝源文稿与固定提交不一致的输入。
4. 在 designs/standards-portal/ 运行 npm ci、npm run build、npm test。本地 Worker/D1 和全部浏览器检查按网站 README 执行。
5. 发布前审查实际 PR diff、测试和目标提交；发布后回读 /version.json，核对静态页面、搜索及四份下载的字节与浏览器行为。

外部命令通过环境变量指定，未指定从 PATH 查找；字体通过配置指定，默认使用可再分发开源中文字体。转换前核验依赖，缺失时在改写产物前报错；临时产物写 temp/，核验记录写 plan/，仅清理本次创建的临时文件。失败保留原因，不部分更新最终交付。

## 正式受控发布的编制配置

以下为正文 4.1、8.11、12.6 要求的配置设计，不能据此声称仓库已有完整正式流水线：

| 建议作业名 | 应配置内容 |
|---|---|
| verify | 干净 Linux 环境核验发布清单内适用字段、Schema、规则、样例及政策来源，报告未覆盖项 |
| no-drift | 复跑不改变任何已提交文件 |
| no-abs-path | 编制/核验工具不依赖本机绝对路径 |
| zip-sync | 提供归档包时，逐成员与受控源文件比对 SHA-256 |
| render | 以 Pandoc、LibreOffice、Poppler 生成 Word/PDF 及渲染记录，版本标签时阻断失败 |

每个合并请求及版本标签执行适用门禁，范围按 12.6.4。正式发布包从标签按固定成员顺序及时间戳生成，给出清单与 SHA-256，不在主线手工维护 ZIP。

核验默认只读，不覆盖已提交记录，显式更新时记录原因。确定性产物的基准时间优先显式 SOURCE_DATE_EPOCH，其次输入版本的提交时间，输出 RFC 3339；提交哈希单列，实际执行时间另列运行日志。

## 配套契约与证据

D2 的对象注册、三阶段 Schema、事件定义、协议子集、兼容及有损规则、夹具和精确预期，须经发布清单绑定及审定。历史研究附件和合成样例不自动升级为正式交付。D3/D4 和具体诊断用途按正文及附录 D/E 的实际前置条件放行。
