# Issue #39–#47 修订条文建议

各段均为征求意见稿之外的候选文字。“原文”仅摘录直接相关语句；“建议条文”未获采纳。除 #39 建议消除正文矛盾外，其余八项建议增加受控样例及其验收说明，不改变业务、权限或 Profile 适用性。样例中的实体、关系和业务决定均为合成；确切键名、规则标识、线格式、错误码和测试向量由对应待决事项审定，不以本稿代定。

## Issue #39 — Segment 条件字段

- 条款：5.1.3、5.1.8、6.4.1、6.4.2、6.4.3、6.4.4、8.11
- 要素：OBJ-021
- 影响的表与 Profile：表 5-1、表 5-4；P-EDT、P-RES，按实际 AI 能力叠加 P-AI。
- 原文：“应包含 `start_ms`、`end_ms`、关联字幕及目标，并满足 0 ≤ start_ms < end_ms ≤ 源时长”；“课件页码、PDF 页码、音频时间、文本段落、图像区域等应使用相应的定位类型分别登记”。
- 建议条文（替换 6.4.1、6.4.2）：Segment 随所属 Resource 版本固定，以所属资源版本为源；应登记定位类型、该类型对应的定位及关联字幕和目标，其他对象以 `owner_ref` 指向所属资源版本。采用音视频时间定位时，`start_ms` 和 `end_ms` 均必填且应满足 0 ≤ start_ms < end_ms ≤ 源时长。课件页码、PDF 页码、文本段落和图像区域分别使用对应的定位成员，不适用上述时间成员或不等式，不应以虚构时间充当定位。类型、字段适用性与表示由 D2 数据契约明确（E12）；6.4.3、6.4.4 保持不变。
- 建议 D2 夹具：分别给出同一确定资源版本上的视频/音频区间、课件页、PDF 页、段落和图像区域；拒绝时间端点缺失、区间倒置或超出源时长，以及非时间定位仅填伪造区间或使用其他格式页码的输入。
- 理由：当前“应包含”可被解读为所有类型必填；两个平台的部分定位能力也不能补造源版本或时间事实。

- 原文：“快照随所在记录写入，不随此后的成员变动而改变”；“评分时，每名成员分别形成评分决定”；“向被评学生及其他学习者展示时应隐藏评价者身份”。
- 建议条文（补充 7.1.4 的 D2 验证说明）：用 G 在提交时由 A、B 组成、随后 B 退出且 C 加入的两条事件，验证历史提交仍为 A、B 的快照，后续小组事件体现其实际形成时成员；同一作品为 A、B 分别形成决定并引用原提交及快照。缺小组引用、缺快照、空快照、提交者不属于快照或用当前名单覆盖旧快照均应判失败。计分互评启用前应同步冻结适用的逐事件契约和 PeerReview 对象样例（E12、E23a），分别检查有授课安排的教师、被评学生及学习者本人获准导出的视图；不得从后两种视图复原受保护的他人评价者身份。计分样例须核对事前约定的比例、校准规则及教师确认，不新增事件词表。
- 理由：平台可管理小组和互评，不等于保存形成时快照、意见可见性与个体评分归属。

## Issue #43 — 提交选择到评分决定

- 条款：6.6.3、6.6.4、6.6.10、7.3.4、7.5.2、7.5.7、7.5.8、7.5.9、8.7.3、9.2.4、9.5.1、9.5.6
- 要素：OBJ-024、OBJ-025、OBJ-034、EVT-013、EVT-014、EVT-017、EVT-019
- 影响的表与 Profile：表 5-1、表 7-2、表 8-4、表 A.9（T07、T08、T20）；P-SUB、P-GRD；AI 提议叠加 P-AI。
- 原文：“已撤回的提交不参与选择”；“调整的更正或撤销追加新记录”；“迟到的旧回执不应推进新更正决定的 `registrar_status`”；“`school_received` 不应展示为已进入学校证据库”。
- 建议条文（补充 T07、T08、T20 联合夹具说明）：受控夹具应按下列顺序列出输入、适用规则标识、各方观察点及预期。选取的课程规则仅为合成的已审定输入，不预设任何学校规则（E23a、E23b；字段与流程契约见 E12）。
  1. 并列给出最高分与教师指定两条分支，合成最高分分支采用已确认分作为比较输入，且不把提议分当作已确认分；撤回高分提交后选取其余有效提交，重新提交须按方案另行选取。分别给出允许、禁止、超时撤回，撤回与未采用事实均保留于对账应送集合。开课后切换方案版本，历史复核仍使用原版本。
  2. 分别给出 `extension`、`deferred_exam`、`course_exemption`、`exam_exemption`、`extra_time`、`substitute_task` 的最小记录；核验个人截止、缓考未完成不计缺交、免修免考不适用及相应缺口和统计分母、替代活动版本引用。更正或撤销追加 `supersedes`，不改写既往判定。
  3. 无持久化时不产生 `submission.submitted`；学校故障时源端已有 `source_recorded_at` 和学生保存凭据，但未入校证据库。续传后先核验 `accepted/queue`，再核验 `accepted/evidence_store`；分别显示学生可见阶段，失败不伪报登记成功。
  4. 依次给出 AI 服务提议、教师用户委托确认、教务归档、更正和旧回执迟到：逐步列出提议与确认决定的 `decision_status`、各确认版本的派生 `registrar_status`、平台确认值、教务正式值及差异。旧回执仅关联旧版本，更正后尚未获教务接收时不把平台更正值冒充正式值。确认使用与 `actor_ref` 一致的真实教师委托；服务凭证确认、委托人与 `actor_ref` 不符或 AI 自行归档均不得通过。
  5. 并列需确认的正式 AI 反馈与课程已启用、符合帮助条件的普通即时解释。前者仅在获授权人员确认后记 `feedback.published`，后者按 `help.provided` 记录，不抬升为正式反馈或评分。
- 理由：平台作业状态和可变成绩不足以核验有效提交、分阶段保存与不可变决定链。

- 建议条文（补充 T09/T10 的 D2 夹具说明）：同一任务分别给出支持、反驳、`inconclusive`、`limits` 的 EvidenceLink；未审查证据不得列入。给出未审查（null 及缺失原因、unknown）、已查无可用证据（空数组、unknown）、已审查但没有足以形成估计的证据（至少一条 inconclusive、insufficient_evidence）的完整记录，对后两类估计状态均拒绝确定掌握值。对照允许按契约表示无方法的原始自我报告、必须引用规程的教师判断和必须引用方法的模型推断；不得借原始自我报告绕过衍生诊断准入。展示 `evidence_window`、`as_of` 和 `valid_until`，交换“记录仍有效、批准到期”和“记录过期、批准仍有效”的组合，均不得用于新的当前判断，获准的历史查阅另行标注。复核维持仅追加状态，复核改变内容追加 `supersedes` 记录；人工复核后批准仍暂停的，不重新放行。缺失表示及控制契约在 E12 冻结，批准边界由 E22 决定。

- 建议条文（补充 T10 批准夹具说明）：对同一方法版本提供课程 S、人群 A 与课程 T、人群 B 的不同批准及后果级别；正例同时满足验证证据、当前批准和记录自身限制，越界或跨级使用应阻断。批准暂停、撤回应追加批准版本，不写回方法记录；离线时仅当可核验证明仍在有效边界内且满足传播约束才可允许，证明已过期、不可验证或已知暂停/撤回时应阻断；已恢复连接后的首次新用途应再次按当前权威结果校验，不自动恢复权限。受控夹具应列出各调用结果及原因，记录有效期、批准有效期与证明传播分别检查；实际时限、阈值与责任由 E22 决定，结构按 E12 冻结。
- 理由：模型开关、历史批准快照或未核验缓存不能充当当前批准；历史查阅另按自身授权处理。
