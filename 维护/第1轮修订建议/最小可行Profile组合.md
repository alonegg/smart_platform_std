# 首批厂商最小可行 Profile 组合建议

建议将首次联调限定为“可靠提交 → AI 评分提议 → 获授权人员确认 → 教务接收／更正”及其身份、授权、事件和回执依赖。4.2、A.1、A.4、A.6 和表 A.9 是能力及用例判定依据，下列为**分角色的最小联调建议**，不是新的 Profile，也不是完整符合性清单。

| 首批角色 | 最少声明 | 首批用例与必须观察的结果 |
|---|---|---|
| 提交源应用 | P-COM + P-SUB | T01 版本与修读关联，T05/T06 重试及乱序，T07 保存与接收/入库及撤回边界，T11 撤权后访问拒绝，T25 写入凭证溯源；提供源端持久化、回执和对账观察 |
| AI 评分提议应用 | P-COM + P-AI + P-GRD（仅提议） | T08-P 提议版本和来源、服务凭证确认被拒，另验证归档拒绝（不承担 T08-C/A 的合法确认/归档）；T11 最小读取与撤权；T23 合成提示注入、越权工具调用等按计划选定场景；T25 认证上下文溯源。只读取已授权的任务输入，不能确认或归档 |
| 非 AI 的确认/归档业务应用（或按正文由校内相应业务方承担） | 接入应用声明 P-COM + P-GRD，按实际承担分别声明操作 | T08-C 真实教师用户委托及匹配主体，T08-A 教务接收与回执，T08-R 更正和旧回执不回退；按事件及权限职责联合核验 T05/T06、T11、T25；如在提交应用中一并承担，应叠加 P-GRD，而非默认由 P-SUB 获权 |
| 一期认知承载与准入（单独验证，不是评分提议应用的前置功能） | 认知应用为 P-COM + P-DIA；实际使用 AI 产生诊断时再叠加 P-AI | T09 证据不足不作确定判断，T10 保留来源与方法、按当前证明阻断越界，合成验证只覆盖结构与准入。不得推出真实方法已批准，也不开放真实诊断或高后果用途（D.2.2、E22） |

**校级公共服务不声明 Profile。** 按 A.8 / 表 A.11 实现标识映射、事件受理与幂等、回执和对账、假名与 AccessGrant、权威评分状态及方法准入；按 T01、T05–T08、T10、T11、T25 的实际交接点联合验证，应用仍须提交自己的副本、缓存、日志和访问拒绝证据。公共服务接口由接入应用身份调用的组件仍按 A.2 声明。

**同时记录两个验收层次：**

1. 工作计划 §2 首批选测为 T01、T05、T06、T07、T08-P/C/A/R、T09、T10、T11、T23（合成选定场景）、T25；T02、T14 留在适配器阶段做离线包往返，仅证明包与历史资产读取部分。完整 T14 还需公共服务正常、第二个独立应用可合法读取历史版本并继续布置任务、提交回传；参考对端不计作独立应用（E26、12.2.6、12.10）。不得把离线结果当作完整接替。
2. 实际放行按表 A.9 逐项补齐，不因首批选测省略：P-COM 基本 T11/T13/T24/T25（视情况 T18/T21）；P-SUB 基本还包括 T13/T14/T15/T16/T19/T26，关键窗口还执行 T17/T18；P-GRD 依阶段执行 T08，另外依实际能力落实 T05/T11/T13/T15/T16/T20/T26，关键窗口执行 T17–T19，只有实际交换题目或交付作答才执行 T03。仅提议方仍提供 T20 提议来源及版本证据。P-AI 基本 T11/T13/T22/T23，界面按实际执行 T16/T26；P-DIA 补齐 T13/T16/T26，并与公共服务联合观察 T10。无界面仍须提供调用所需状态与错误，不以合成测试替代适用的师生任务、外发、安全、权利或运行验证。

P-RES/P-EDT 仅在实际承担独立资源读取/运行或编辑发布时按表 A.9 分别纳入；读取评分任务已获授权的输入不等同承接独立资源工具能力。P-SIM、P-RSB、完整交互题库和认知算法不列入本次最小组合。受理、提交、提议、确认与归档分别保留责任、观察点和证据，不以一个厂商的局部通过替代联合链路。
