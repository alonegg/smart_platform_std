# 未来智慧教学平台数据资产层标准体系

研究设计稿 v0.1｜2026-10-23｜拟议校内规范

## 一、范围、术语和采用原则

本体系规定三层架构中数据资产层的共同模型，以及课程资源、教学过程、学生认知状态的组织、交换和治理规则，并约束接入应用的读写行为。学校正式发布前，本稿中的“应”“不得”表示拟议要求，不表示已经实施或取得国际认证。

“应”为本稿要求，“宜”为建议，“可”为可选能力。国际标准中自身规定的强制字段、语义和协议行为，应由对应适配器完整遵循；校内扩展不得改写国际标准的含义。

| 术语 | 本体系含义 |
|---|---|
| 数据资产 | 内容或记录，加身份、来源、关系、版本、权限、质量和生命周期信息 |
| 数据契约 | 对象模型、字段语义、操作权限、交换方式及失败行为的共同约定 |
| Profile | 在选定标准之上明确本校必填项、词表、场景和验证规则的应用约束 |
| 学习证据 | 可定位、可核查的作答、作品、观察、反馈或其他教学事实 |
| 认知状态 | 对特定目标、时间和条件下理解或能力表现的观察、估计或判断 |
| 规范化记录 | 经统一标识、字段和语义转换，仍保留来源及转换信息的记录 |
| 互操作 | 在明确范围内交换后仍能正确解释、使用并继续产生数据 |

本体系采用“共同核心模型＋场景 Profile＋标准适配”的方式。课程和证据先具备一致语义，再按 Common Cartridge、QTI、xAPI、CASE、LTI 等各自职责交换。采用研究见《03_标准研究与采用说明》；本稿中的对象和字段是本轮校内设计，不宣称是国际标准原有字段。

## 二、标准目录及分工

| 编号 | 规范名称 | 核心内容 | 主要成果 |
|---|---|---|---|
| S0 | 总则、术语与公共数据模型 | 身份、版本、关系、权威来源、空值语义 | 共同对象字典与标识规则 |
| S1 | 课程资源结构与语义规范 | 课程组织、资源、题目、目标、量规、表示形式 | 课程对象、资源元数据及关系集 |
| S2 | 教学过程资源与学习证据规范 | 活动、事件、作品、反馈、成绩决定 | 事件词表、证据链与指标口径 |
| S3 | 数据交换与接口规范 | 包、API、同步、适配、冲突与回执 | 交换 Profile、接口契约与映射报告 |
| S4 | 应用与 AI 能力接入规范 | 能力声明、授权范围、返回结果与退出 | 应用登记、能力契约与准入场景 |
| S5 | 学生认知状态与学习诊断规范 | 状态维度、证据、量尺、方法、不确定性 | 可解释、可迁移的认知记录 |
| S6 | 数据安全、权利与生命周期规范 | 分类分级、用途、留存、更正和删除 | 保护目录、权限矩阵与处置流程 |
| S7 | 数据质量与一致性验证规范 | 完整性、语义、可靠性、独立使用 | 互操作用例、质量报告与复验规则 |

S1、S2、S3、S4 延续原材料的职责与编号；S0 提取共性规则，S5 将认知状态独立细化，S6、S7 汇集贯穿各规范的治理和验证要求。实现单位不得为每个规范另建互不兼容的课程、学习者或版本定义。

## 三、S0：总则与公共数据模型

### S0-01 统一身份与对象引用

每个业务对象应具有稳定 object_id，每个已发布或已确认内容版本应具有不可变 version_id。schema_version 表示数据结构版本，profile_version 表示场景约束版本，二者不得与内容版本混用。object_ref 统一包含 object_id 和 version_id；需保留历史含义的引用不得只指向 latest。

外部标识应单独登记 source_system、source_id 和映射状态。不得按同名课程、同名学生或同名知识点自动合并。对尚无映射的数据，进入待处理状态，保留原始来源，不丢弃或伪造学校编号。

### S0-02 课程与修读分离

Course 表示长期课程身份；CourseVersion 表示课程内容版本；Offering 表示某学期或批次的开课；Enrollment 表示学习者在该开课中的参与关系；学习者一次修读包含多个 Attempt。学校可在具体业务 Profile 中定义一课一班、共建课程、补考和重修规则，不把某一规则写成所有教学场景的固定限制。

### S0-03 公共字段

| 字段组 | 最低字段 | 规则 |
|---|---|---|
| 身份和版本 | object_id、object_type、version_id、schema_version | 标识不因显示名称变更而改变 |
| 来源 | source_system、source_id、created_at、created_by | 来源和写入身份经服务端核验 |
| 关系 | object_ref、course_ref、offering_id（按场景） | 精确到当时版本；引用必须可解析或明确受限 |
| 权利和保护 | rights_ref、access_policy_ref、classification_ref | 管理、版权和个人信息权限分别处理 |
| 状态 | lifecycle_status、review_status、supersedes | 草稿、发布、撤回、更正分列 |
| 完整性 | content_hash、byte_length（文件适用） | SHA-256 用于字节一致性，不代替来源认证 |

跨系统对象使用 URI/UUID 等无歧义标识；国际标准要求 IRI 的位置使用受控 IRI。示例中的 example.edu 仅用于说明，正式命名空间由学校登记管理。

### S0-04 时间、单位与缺失值

交换时间使用带时区的 RFC3339 表示，统一存储策略由实施确定，用户展示按适用时区。occurred_at 是事件发生时间，received_at 由接收侧生成；时间戳不作为唯一排序依据。视频位置采用毫秒，文件大小采用字节；评分必须带量尺和上下界。

缺失值应区分 unknown、not_collected、not_authorized、source_unsupported、not_applicable。0 只表示真实零值，空数组只表示已知集合为空。新系统不得根据缺失日志补造历史学习记录。

### S0-05 权威写入与修订

每个对象类型指定权威写入方及允许操作。草稿可以编辑，已发布版本和已确认教学事实通过追加新版本或更正记录修订。应使用预期版本或条件更新检测并发冲突，禁止最后写入静默覆盖正式记录。

### S0-06 扩展管理

扩展应使用注册命名空间，声明字段、语义、敏感性和兼容策略。未知扩展可保留原文，但消费者必须声明是否理解。核心对象不能仅以不可解释的整块 JSON 或私有二进制替代。标准升级须提供版本差异、迁移规则、验证样例和退役安排。

## 四、S1：课程资源结构与语义

### S1-01 课程的最小组成

每个发布课程版本应声明大纲、教学目标、章节或学习单元、资源、学习活动、评价规则和权利信息。知识图谱、能力框架、案例、参考资料、AI 辅导配置根据课程类型登记适用性。缺项应有明确原因和审核结果，不能用空文件通过完整性检查。

### S1-02 资源与表示形式

ResourceVersion 应保存资源类型、标题、语言、作者或责任主体、来源、许可、适用对象、教育用途、媒体类型、字节数、校验值及可访问引用。每种表示形式单独登记 representation_kind：editable_source、reading_copy、runtime_package 或 media_derivative，并记录转换关系。

PPTX、ODP、HTML、PDF、视频、EPUB、H5P 等是不同类型的表示形式，不能相互替代完整性声明。课件可编辑性、数学公式、动画、交互行为、字幕及无障碍能力分别检查。

### S1-03 时间与空间定位

SegmentVersion 应包含源资源版本、start_ms、end_ms、关联字幕及目标；必须满足 0≤start_ms<end_ms≤源时长。课件页码、PDF 页码、音频时间、文本段落或图像区域使用相应定位类型，不以模糊的“第几页”跨格式混用。源内容变化后，相关定位须重新验证。

### S1-04 知识与能力关系

知识点、学习目标和能力要求分别具有稳定标识及版本。关系至少区分 part_of、prerequisite_of、explains、assesses、supports、aligned_to；关系包含来源、建立方法、审核状态和适用范围。跨课程的 aligned_to 不自动表示两项目标等价。CASE 用于对外交换目标、能力与框架关系，学科特有误解关系保留为校内扩展。

### S1-05 题目与评价量规

AssessmentItemVersion 应保存题干、媒体、交互类型、作答结构、评分规则及目标映射。题目、正确答案、解析和量规应能分别授权。QTI 适配器应声明支持的题型、响应处理与自定义交互，不支持部分应生成损失报告，不能只导出题干却标记为完整测验迁移。

### S1-06 课程版本与发布

草稿、待审、已发布、撤回、归档应有明确转换责任。内容更新发布新版本；曾用于作答的版本在合法留存范围内可追溯。撤回公开访问与删除历史记录是不同操作，须分别处理。

### S1-07 AI 生成内容

AI 产物应记录输入资源版本、生成任务、模型或服务版本、生成时间及人工审核状态。提示策略可版本化；API key 和运行凭据不得进入课程资产。生成内容未经必要审核不得自动覆盖发布版本。

### S1-08 过程资源再利用

将课堂讨论、学生作品或辅导记录转成课程资源时，应生成新的资源对象，完成必要的个人信息处理、权利确认和内容审核，保留 derived_from。原场景的教学访问权限不得自动扩展为公开传播或后续训练授权。

## 五、S2：教学过程资源与学习证据

### S2-01 事件与作品共同保存

学习事件记录事实发生，ProcessArtifact 保存作品、批注、讨论或实验结果；Submission 将有效提交与具体作品版本关联。关键提交应能重建“任务版本—作品—帮助—反馈—评分决定”的链条。内容存储与事件传输可分开，但引用必须在授权范围内稳定解析。

### S2-02 事件公共结构

校内事件信封至少包含 event_id、schema_version、profile_version、source_system、source_event_id、actor_ref、offering_id（开课场景必填）、enrollment_id（学习者修读场景必填）、action、object_ref、occurred_at、received_at、context、payload_hash。课程发布等非开课事件的场景字段按相应 Profile 约束。结果、作品和证据通过受控引用关联。actor 的权限由服务端鉴别，不能只相信客户端自报角色。

校内信封不是 xAPI Statement。选择 xAPI 传输时，应按官方结构输出 actor、verb、object 等合法字段，并将校内扩展放入允许的位置；校内接收回执与 xAPI 协议响应分别处理。

### S2-03 最小事件词表

| 类别 | 校内事件 | 必要业务语义 |
|---|---|---|
| 课程及权限 | course.published、enrollment.changed、permission.revoked | 内容版本、名单有效期及权限撤销依据 |
| 资源学习 | resource.opened、media.progressed | 资源版本、有效播放区间、采集能力与缺失 |
| 教学活动 | activity.started、discussion.posted、guidance.recorded | 活动版本、讨论作品、教学人员确认 |
| 作答提交 | response.recorded、submission.saved、submission.submitted | 尝试、草稿/正式提交区分、作品与持久化回执 |
| 支持与反馈 | help.requested、help.provided、feedback.published | 帮助级别、反馈来源及适用对象 |
| 评价与归档 | grade.proposed、grade.confirmed、grade.corrected、grade.archived | 提议、确认、更正及归档不同状态 |
| 认知与行动 | cognition.updated、recommendation.issued、intervention.recorded | 只引用认知/推荐对象，不把推断记成原始作答事实 |

各应用按能力声明承诺其实际承担的事件子集；涉及有效提交、教师确认、撤权的关键事件不得用其他统计指标替代。

### S2-04 xAPI Profile 与 Caliper 适配

本校应冻结场景词表、verb IRI、活动类型、context 要求、Statement Template、必填扩展和示例序列。相同动作不同语义不得只靠 display 文本区分。学习者优先使用受控 account 标识，避免把姓名、邮箱直接放入流转记录。

Caliper 接入可映射到共同模型，但原始载荷、映射版本与损失信息应保留。相同事实经两种协议进入时，应按业务唯一键去重。不能承诺 xAPI 与 Caliper 全字段无损互转。

### S2-05 提交、评分与更正

Attempt、Submission、Feedback、GradeDecision 分别建模。AI 或规则引擎输出为 proposed；教师确认形成 confirmed 决定；教务接收形成 archived 状态。更正追加新决定并引用 supersedes，不能覆盖初次修读、历史量规或原提交。

### S2-06 幂等、乱序与迟到

以 source_system＋source_event_id 识别源事实；相同键相同内容返回 duplicate，相同键不同内容产生 conflict，进入核查。接收端保留发生与接收时间、水位和必要源序号；迟到事件可追加并触发受影响统计或认知状态重算，旧结果保留为历史版本。

### S2-07 统计口径

指标必须携带统计窗口、分母范围、去重键、规则版本、数据覆盖率和缺失说明。作业提交率按应提交学生集合计算，草稿不计有效提交；视频覆盖率按区间并集计算，重复播放不累计超过 100%。观看、参与、完成、通过和掌握分别定义。

### S2-08 不采集与不推断的边界

本版教学资产层不纳入人脸识别、情绪识别或基于外貌的认知推断。不得把技术日志直接作为学生能力、教师教学质量或违规结论。需要专项考试安全的场景另行界定，不扩大本体系的采集范围。

## 六、S3：数据交换与接口

### S3-01 采用组合与边界

课程结构及资源对外兼容 Common Cartridge 1.3，1.4 作为候选试验；题目采用 QTI 3 并对既有 QTI 2.x 明确转换；目标和能力采用 CASE 1.1；学习记录以 xAPI 2.0 为新建方向，兼容 1.0.3；远程教学工具采用 LTI 1.3 与需要的 LTI Advantage 服务。各自的精确版本和支持范围写入能力清单。

cmi5 Quartz 规范明确引用 xAPI 1.0.3，因此 cmi5 运行场景须保留其兼容端点或适配层，不能直接替换版本标识为 2.0。SCORM 1.2/2004 作为既有课件兼容路线；既有包中没有的数据不能由适配器虚构。上述为采用决策，具体官方版本与核验边界见研究说明。[R01—R10、R12]

### S3-02 校内交换包

本校包称为“教学资产交换包”，不是新的国际课件标准，也不以自定义 manifest 冒充 Common Cartridge。包中可以包含规范的 CC、QTI、H5P 或 EPUB 子包及其原始清单，另用学校 manifest 连接无法由单一标准表达的证据、认知状态和治理信息。

包至少包含 manifest.json、objects/、assets/、relations/、rights/；按 Profile 可增加 events/、evidence/、cognition/、mappings/。manifest 声明 package_id、schema_version、profile、export_scope、对象版本、文件长度与 hash、依赖、权限、导出时间以及适配损失。

### S3-03 包的四种 Profile

| Profile | 允许内容 | 默认排除或限制 |
|---|---|---|
| teaching | 经授权的课程结构、资源、目标、公开活动、必要运行依赖 | 学生身份、历史作答、个体认知状态、未公开答案 |
| migration | 指定课程/开课范围内获准迁移的内容、过程、认知和映射 | 身份映射和答案独立受限；不自动延续原应用权限 |
| archive | 指定范围内合法留存的版本、提交、评价及必要审计 | 只供归档、恢复、申诉等批准用途 |
| research | 经专项批准的数据集、转换说明、变量及缺失信息 | 不默认包含直接身份；去标识化不等于匿名化 |

研究 Profile 是可选扩展，不能替代教学服务的正常访问授权。认知状态导入必须保留方法和量尺，不因包导入成功就证明新应用能继续使用该模型。

### S3-04 文件完整性和独立使用

在线包可引用学校受控的大文件对象，但须声明存储范围、对象版本、字节数、hash 和权限取得方法。独立归档包必须携带必要字节或具备已验证的独立恢复路径。临时签名 URL 只用于交付，不作为唯一长期引用。

Thin Common Cartridge 和 LTI 链接解决远程访问，不保证离线保存、可编辑源取得或工具停止服务后的可用性。每个包应声明 portability_level：references_only、content_available 或 independently_restorable，并附验证结果。

### S3-05 导入流程

导入依次执行文件安全、大小和解压限制、清单结构、校验值、对象引用、权利、版本兼容与语义检查；先生成 dry-run 差异报告，再按授权提交。路径穿越、重复成员、超大解压比、无法解释的核心对象、缺失关键文件均须阻断导入。未知扩展可以隔离保留，不得静默丢弃。

### S3-06 API 设计基线

校内 HTTP API 候选采用 UTF-8 JSON、JSON Schema Draft 2020-12 和 OpenAPI 3.1.1。3.1.1 是本稿选择的文档基线，不称为当前最新版本；实施前按工具支持冻结精确版本。Schema 的 format 校验是否执行必须显式配置。[R22、R23]

| 服务组 | 必需操作 | 操作边界 |
|---|---|---|
| 主数据与映射 | 获取快照、变更、水位、外部标识映射 | 不擅自改写权威身份和教务记录 |
| 课程与资源 | 查询版本、登记草稿、提交审核、获取发布结果 | 发布权限与普通写入分开 |
| 证据与事件 | 提交作品、批量事件、查询回执、对账及补传 | 逐项返回状态，正式提交持久化后确认 |
| 认知状态 | 登记方法、写入估计、读取依据、更正或失效 | 与正式评分权限分开 |
| 导入与导出 | 创建任务、查询进度、读取差异、下载结果 | 范围与用途在任务创建时冻结 |
| 授权与审计 | 应用注册、撤权、查询获准操作的审计 | 人员身份与服务身份分离 |

这些是待实现的接口职责，不表示已有生产端点。本轮不将说明性路径或合成样例称为已完成 API。

### S3-07 回执与故障语义

通用业务回执至少区分 accepted、duplicate、rejected、quarantined、conflict，并给出可查询 receipt_id、错误码和字段定位。accepted 必须说明持久化边界，例如校内可靠队列或证据库；不得用 HTTP 200 代替业务成功。

学生提交状态区分“本应用已可靠保存”“已进入学校证据库”“教师已确认”“教务已归档”。故障时可靠排队并提示同步状态，恢复后按唯一键重放。权限失效时停止新的敏感访问，不通过缓存绕过撤权。

### S3-08 同步与对账

全量快照、增量批次和事件推送各自声明游标、截点、水位、删除和退课语义。对账以逻辑唯一记录计数：应送集合＝有效入库＋隔离待处理＋明确拒收＋待送/待收；重试请求单列。完成对账并不表示拒收或隔离数据已经可用。

试点验收时，关键提交和成绩确认的未解释缺口应为 0。正常同步、离线补传和灾后恢复分别测量。可讨论 P95 正常同步不超过 5 分钟、离线恢复后 24 小时内补传、关键读取 RTO 不超过 4 小时；这些只是待测算的建议值。源端延迟、可靠队列故障边界、RPO 和最大允许撤权延迟须同时定义，不能只检查下游。

### S3-09 协议与语义分层

标准适配器保留原始记录、规范化记录及 mapping_version，记录一对多、多对一、未映射和有损转换。xAPI Statement 使用其自身更新/voiding 语义；校内更正和依法删除流程不得通过修改原 Statement 伪装完成。LTI AGS 的分数回传进入学校评价流程，不能直接等同教务正式归档。

## 七、S4：应用与 AI 能力接入

### S4-01 应用能力登记

应用登记应说明应用标识、版本、实例、服务责任、支持的标准版本、对象类型、交换方向、Profile、事件集、访问目的和期限。支持一种标准的声明必须细化到实际功能；不能用“兼容 xAPI”“支持课件导出”替代能力明细。

### S4-02 授权模型

使用角色、课程/开课/对象范围、用途和时间等条件共同控制权限。人员登录与后台服务授权分别管理。学生访问本人获准资源和记录；教师访问任教范围；管理者优先使用经过批准的聚合视图；加工工具只访问指定素材；认知服务只取得必要证据。

### S4-03 接入 Profile

正式教学应用须具备关键提交、反馈、评价确认、撤权、证据导出和故障恢复能力；专项能力服务按输入输出契约接入；研究试验应用在明确沙箱和用途内运行。应用等级是学校内部管理规则，不等于国家监管资质或国际认证。

### S4-04 AI 服务任务契约

AI 服务请求应包含 task_id、输入对象版本、允许操作、输出结构、帮助策略和权限；返回结果应包含输入版本回显、模型/服务版本、生成时间、结果对象、错误或质量提示及审核状态。服务失败可重试，旧资源仍可访问。模型升级应重验输出格式和已知任务集。

### S4-05 人工责任

AI 可提出题目、反馈、认知判断和学习建议；正式课程发布、需确认的评分及重要教学干预由获授权人员决定。AI 返回的文字或工具调用不得直接提升自身权限或修改正式记录。

### S4-06 变更与退出

接口、模型、数据范围或部署环境变化应有影响评估。退出时导出获准资产、完成核对、撤销账号和服务令牌、处理缓存与副本、登记保留和删除结果，并验证另一应用可以继续访问所需历史资源与证据。

## 八、S5：学生认知状态与学习诊断

### S5-01 范围

本规范支持与学习目标相关的理解、技能、迁移应用和误解判断，不构建医学、人格、情绪或固定智力档案。认知记录只在明确目标、时间、量尺和任务条件下解释。

### S5-02 三种核心对象

EvidenceLink 描述某条证据如何支持、反驳或尚不能确定某个判断；CognitiveState 描述特定维度状态及其方法；LearningRecommendation 描述基于状态提出的下一步行动。教师诊断和学生自我报告使用 CognitiveState 的不同 origin_type 保存，不与模型估计混为一项。

### S5-03 最小字段要求

| 字段 | 类型/要求 | 语义 |
|---|---|---|
| state_id、version_id | 标识，必填 | 认知记录及其不可变版本 |
| learner_ref、enrollment_id | 引用，必填 | 明确学习者与修读范围 |
| target_ref | 对象及版本，必填 | 知识、目标或能力；允许 CASE 映射 |
| dimension | 受控词表，必填 | 如 conceptual_understanding、procedural_skill、transfer、misconception |
| origin_type | 枚举，必填 | observation、model_inference、teacher_judgment、self_report |
| status | 枚举，必填 | unknown、insufficient_evidence、estimated、reviewed、stale、invalidated |
| value、scale_ref | 值与量尺，条件必填 | 只在状态支持且量尺定义清楚时赋值 |
| uncertainty | 对象，必填 | 类型、来源及解释；无可靠估计时写 not_estimated |
| evidence_refs | 引用列表，必填 | 具体作答/作品/反馈及其证据作用；unknown 可为空 |
| method_ref | 方法及版本，条件必填 | 推断模型、评分规则或人工判断规程 |
| context | 对象，必填 | 任务难度、独立/辅助、尝试、语言等相关条件 |
| evidence_window、as_of、valid_until | 时间，必填 | 使用了何时证据，何时形成及何时需要重新确认 |
| review、supersedes | 对象/引用，按状态 | 人工复核、更正及历史关系 |
| purpose、access_policy_ref | 受控用途与权限，必填 | 允许如何使用该记录 |

### S5-04 量尺与概率

认知值可以是类别、量规等级、连续测量值或概率，但必须明确含义。0.8 不能在一个系统表示“正确率”、在另一个系统表示“掌握概率”。概率输出应说明目标事件、估计方法及校准证据；模型生成的自信语句不能充当统计置信度。不同方法或量尺未建立映射前不得直接平均、比较或排序。

### S5-05 证据规则

估计或判断应引用可解析证据；明确证据是支持、反驳还是限制，保存采集来源、任务版本、AI 帮助条件和时间。一次答对、猜测、重复同题、看过答案和独立迁移任务分别标记。模型内部推断过程不是可替代学生作品的学习证据。

### S5-06 缺失、过期与冲突

unknown 或 insufficient_evidence 不得输出确定掌握值；过期记录标为 stale，失效依据导致记录 invalidated。不同模型或教师意见可以并存，保留分歧和适用范围。汇总视图须声明选择规则，不能静默选择最高分或最新时间。

### S5-07 误解的表达

Misconception 使用误解概念及证据关系，不以“粗心”“能力差”等固定标签替代解释。误解是待检验假设，应允许反证、消除或更正。例如“混淆边际量与平均量”需要对应题目、解释文本和教师或方法依据。

### S5-08 推断方法登记

方法登记应包含 model_id、model_version、适用学科与人群、输入字段、输出量尺、训练或规则来源说明、验证数据范围、限制、漂移监测和撤回条件。规则法、BKT、IRT、深度模型或大模型均遵守同一输出契约，首版不强制某种算法。

### S5-09 迁移与更新

交换 CognitiveState 时应同时提供量尺、方法说明和获准证据引用。接收方若无法解释方法，则作为历史报告展示，不能假定其概率具有相同校准意义。证据被更正或依法删除后，应更新相关状态及用途限制；不能保留失去依据的确定判断。

### S5-10 学习行动建议

推荐至少包含推荐对象、目标、理由、证据、活动或资源引用、难度/支持方式、有效期、产生方法及教师/学生反馈入口。可建议复习片段、补充解释、迁移练习、请求教师指导等具体行动。推荐后应记录是否接受、实施及后续表现；“被点击”不等于“学习有效”。

### S5-11 学生可见与复核

学生应能理解“这项判断针对什么、基于什么、何时更新、有何局限”，并提供更正和申诉通道。教师应能看到原始证据与模型建议的区别。教学管理使用须另行明确用途，不默认将个体认知状态用于跨课程排名或重要资格决策。

### S5-12 方法验证与教育效果

接口和字段验证只证明记录能够交换。认知方法还须验证测量目标与题目匹配、独立样本表现、时间或课程外推、不同学习条件下的误差及校准；推荐效果需要适当的教学评价设计。数据互通测试、模型离线指标、真实教学效果是三项不同结论。

## 九、S6：安全、权利与生命周期

### S6-01 标准依据和适用范围

以 JY/T 0643—2025《智慧教育平台 个人信息保护通用要求》作为个人信息保护的行业依据；分类分级参照 JY/T 0661—2025《教育数据分类分级指南》。本校三类教学资产是业务划分，须进一步映射到行业分类及安全分级，不能把 A/B/C 数据域当成法定安全等级。后者区分核心数据 L5、重要数据 L4、一般数据 L3—L1，并将覆盖高校全校范围的相关学生、教职工、教学管理和科研管理数据列入 L3 识别情形之一；应结合数据集整体范围及其他识别条件定级，不能因单条记录不敏感就将汇聚库按低等级处理。[R16、R17]

### S6-02 权利与用途分开

每项资产登记管理主体、内容权利、许可条件、个人信息处理目的和访问范围。教学复用、公开传播、科研利用与模型训练分别判断，不通过一次教学授权自动扩展全部用途。受限材料不得因加入课程包而改变权限。

### S6-03 个人信息最小化

learner_ref 与真实身份映射分区保存，转换及解析受独立授权；去标识化记录仍可能属于个人信息。应用按当前任务获得最少字段，认知数据与原始作品设置受控访问。外部处理、模型训练和长期留存须单独登记适用条件。

### S6-04 数据生命周期

每类对象规定收集目的、保留依据、期限制定责任、到期处理和例外保全。原始音视频、教学成片、作答、认知状态、正式评价及审计分别管理。不得统一永久保存。规范实施前应完成保存期限表及个人信息处理活动审查。

### S6-05 更正、删除与证据完整性

不可变版本指防止静默覆盖，不表示拒绝依法更正或删除。删除操作应处理主存储、索引、向量索引、缓存、导出副本和备份的适用周期，记录执行结果与合法保留依据。保留不泄露被删内容的必要处置审计；受影响的统计和认知结论须失效或重算。

### S6-06 审核与访问控制

课程内容的发布和更新按学校审核流程完成。涉及对接国家智慧教育平台的资源，按其内容审核与入库出库规范核查适用要求；校内流程可借鉴，不能混同适用范围。API、包导出和后台运维访问均须审计。[R18、R19]

### S6-07 安全与可恢复

传输及存储保护、密钥托管、最小权限、审计保护、异常告警和恢复演练贯穿三层。恢复后应检验内容、权限、版本引用和关键提交，不能只检查服务启动或文件 hash。正式安全等级和具体控制基线须结合系统用途确定。

## 十、S7：质量与一致性验证

### S7-01 验证分层

结构验证检查字段和格式；语义验证检查对象关系与词表；业务验证检查发布、提交、评分和撤权流程；互操作验证检查独立应用使用；教育验证检查内容质量及认知方法有效性。通过某一层不能替代其他层。

### S7-02 最小互操作测试集

| 用例 | 执行内容 | 通过依据 |
|---|---|---|
| T01 标识与版本 | 同一课程两个版本、两个开课和两次修读 | 无误合并，旧作答引用旧版本 |
| T02 完整课程包 | 导出后在独立环境读取课程、资源和关系 | 声明范围内文件可用、关系完整、损失已声明 |
| T03 题目往返 | 代表性题型导出、导入、作答和评分 | 题干、交互和评分语义一致；不支持项明确 |
| T04 交互内容 | 验证运行依赖、无障碍与离线边界 | 按声明能力运行；缺依赖不伪装成功 |
| T05 事件重试 | 相同事件重送及同键不同内容 | 正确去重，冲突可见，无静默覆盖 |
| T06 乱序迟到 | 事件顺序打乱、延迟到达与重新计算 | 保留发生/接收时间及历史结果，状态正确 |
| T07 提交故障 | 在确认提交前后制造连接和服务故障 | 可靠保存边界清楚，恢复后可对账 |
| T08 评分责任 | AI 提议、教师确认、教务归档和更正 | 权限正确，各决定可追溯 |
| T09 认知缺证据 | 只提供观看事件或无有效作品 | 输出 unknown/insufficient_evidence，不认定掌握 |
| T10 认知迁移 | 不同量尺/方法记录导入另一应用 | 不混算；保留方法、不确定性和证据范围 |
| T11 越权与撤权 | 跨学生、跨班、未公开答案及退课后请求 | 拒绝越权，撤权延迟可测，缓存受控 |
| T12 权利与包隔离 | teaching 包导出 | 不带学生历史、个体认知与受限答案 |
| T13 资料修订 | 证据更正、失效或依法删除 | 下游状态同步失效/重算，审计可追溯 |
| T14 第二应用 | 原应用不可用时读取资产并布置新任务 | 可合法读历史、产生新提交并回传 |
| T15 恢复与对账 | 故障恢复、文件和事件集合核对 | 关键记录无未解释缺口，权限和引用正确 |
| T16 人可理解 | 教师与学生查看状态、依据及错误说明 | 能理解来源、限制并完成更正或重试 |

T01—T16 是本轮验证设计，尚未在真实平台执行。本轮随附的 JSON 是合成说明样例；其结构检查不能视为国际认证、真实教学或认知有效性验证。

### S7-03 质量报告与阻断项

报告应包含对象范围、数据量、抽样方法、时间窗口、应用版本、规则版本、执行环境、结果、失败样例和未覆盖项。缺失关键提交、越权、答案泄露、历史版本覆盖、未经人工确认的正式评分以及无法恢复声明范围的资产，应阻断相应场景通过，不用总体通过率抵消。

## 十一、实施顺序与首版冻结项

第一阶段完成共同标识、课程结构、过程证据、权限与导入导出，验证课程和历史记录可独立使用。第二阶段发布学校 xAPI Profile、QTI/CASE 映射及应用接入规则，完成双应用的读写验证。第三阶段选择具体学科和评价目标，验证认知状态模型、教师反馈与学习行动闭环。

| 待冻结事项 | 本稿建议 | 决定依据 |
|---|---|---|
| 标准发布与维护责任 | 教学业务、信息技术、课程组共同治理 | 校内职责及发文程序 |
| 目标/能力及评分量尺 | 从试点课程定义，逐步建立跨课映射 | 学科内容与评价证据 |
| 协议与精确版本 | 按研究矩阵选用并冻结校内 Profile | 实际工具支持与互操作结果 |
| 同步、撤权、RPO/RTO | 分关键提交、普通事件和资源文件设置 | 规模、源端能力和故障演练 |
| 个人信息与保留期限 | 分类制定，写入可执行策略 | 适用要求、业务目的与审查 |
| AI 帮助和正式确认规则 | 按活动和课程类型配置 | 教学目标与评价公平性 |
| 试点验证范围 | 至少两个独立应用和代表性课程场景 | 资源类型、权限和学习证据覆盖 |

本稿已定义标准体系及主要规则；完整生产 JSON Schema、OpenAPI 实现、国际标准认证和真实教学验证应按冻结后的 Profile 开展，不能由本次文档研究推定完成。
